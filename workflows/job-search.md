# Find and evaluate opportunities

For a general job search, aim for 3 to 5 distinct, verified openings. Use the user's requested count when given. When the search scope allows, try equivalent titles and check multiple employers while honoring the user's criteria. Continue past the first match when the search calls for multiple results.

1. Read target roles, location, work arrangement, compensation preferences, and the experience library. Use any criteria the user gave for this search. If an incomplete profile leaves the search direction unclear, follow `onboarding.md` to propose a direction from the available materials for the user to review. Leave optional filters open and ask only about unresolved constraints that materially affect the search.
2. Use the host's available web search or browser tools. Prefer a current employer careers page for verification. If browsing is absent, accept a pasted listing. If access requires sign-in or human interaction, follow the host's handoff process; do not bypass barriers.
3. For each promising role, verify title, employer, location, salary if actually disclosed, and application availability. Record what is unknown. Distinguish the employer's listing from aggregators and don't invent live openings.
4. Save the actual listing text, canonical URL, key requirements, specific experience matches, and genuine gaps with `job add`. The helper timestamps capture and rejects repeated canonical URLs. For missing URLs or distinct URLs for one posting, inspect existing jobs to avoid duplicates.
5. Start discovered opportunities as `saved`. Queue a job only when the user requests an application; preserve their request. User-provided URLs still require reading the listing before tailoring.
6. Rank the shortlist by the person's priorities and evidence. Avoid numeric success predictions. Save dates only when known.
7. Validate and rebuild. Show each saved match in rank order with its title, employer, listing link, and brief fit reason. If fewer than the target qualify, return the matches you could verify and briefly describe where you searched and any limits that narrowed the results. Never substitute demo listings for live research.
8. If the user needs to choose what to pursue, recommend one role from the shortlist to review first. Give a concrete reply they can use, such as "Say 'Prepare me for [role] at [company]' and I'll return your tailored resume and interview prep." If a wider search could help and would require changing a stated preference, propose one specific adjustment for the user to approve.

When the user replies that they are interested in a specific role, proceed with research, the finished resume and starter interview prep under `application.md`. If they specify a narrower task, follow that scope.
