# Find and evaluate opportunities

For a general job search, aim for 3 to 5 distinct, verified openings. Use the user's requested count when given. When the search scope allows, try equivalent titles and check multiple employers while honoring the user's criteria. Continue past the first match when the search calls for multiple results.

1. Read target roles, location, work arrangement, compensation preferences, and the experience library. Use any criteria the user gave for this search. If an incomplete profile leaves the search direction unclear, follow `onboarding.md` to propose a direction from the available materials for the user to review. Leave optional filters open and ask only about unresolved constraints that materially affect the search.
2. Use web search, job boards, and previous searches to discover leads. Open the employer's careers site or its authorized hiring system to read the exact posting. Confirm the title, employer, location, requisition ID when available, and salary if disclosed. If browsing is unavailable, accept pasted listings as unverified leads.
3. Check the posting and its application route as described under **Check listing availability**. Search snippets, cached copies, posting dates, and aggregator badges are discovery evidence only. Use the employer's direct posting URL in the results.
4. Save the actual listing text, canonical URL, key requirements, specific experience matches, genuine gaps, and a `fit_assessment` when there is enough detail to assess the role. Use `job add` for a new listing and `job update` to reassess a saved one. The helper timestamps capture and rejects repeated canonical URLs. For missing URLs or distinct URLs for one posting, inspect existing jobs to avoid duplicates.
5. Start discovered opportunities as `saved`. Queue a job only when the user requests an application; preserve their request. User-provided URLs still require reading the listing before tailoring.
6. Rank the shortlist by the person's priorities, eligibility, and evidence match. Flag blockers such as an unmet license or a conflict with a confirmed location constraint even when the score is high. State which blockers remain unverified. Save dates only when known.
7. Immediately before sharing the shortlist, do the final availability pass below, then validate and rebuild. For each verified role, show its title, employer, checked posting link, saved evidence match percentage when available, strongest reason to consider the role, and most important gap or eligibility issue. Include when the openings were checked. Describe the percentage as weighted coverage of assessed criteria. If fewer than the target qualify, continue checking other leads within scope. If there are still fewer, return the verified matches and briefly describe where you searched and what limited the results.
8. If the user needs to choose what to pursue, recommend one role from the shortlist to review first. Give a concrete reply they can use, such as "Say 'Prepare me for [role] at [company]' and I'll return your tailored resume and interview prep." If a wider search could help and would require changing a stated preference, propose one specific adjustment for the user to approve.
9. After reporting the result of a search, including a search with no verified openings, offer an optional email review in chat. For example, “Would you like me to check your email for recruiter messages, application updates, or interviews from the past three months? You can also give me a specific date or date range.” Respect any prior decline or narrower request. If the user already requested the review, carry it out using `correspondence.md`.

When the user replies that they are interested in a specific role, proceed with research, the finished resume and starter interview prep under `application.md`. If they specify a narrower task, follow that scope.

## Check listing availability

- **Open.** Navigate to the employer or authorized hiring-system detail page in a live browser, or use a direct fetch that shows the current posting and application route. Inspect the final page after redirects. Confirm that it matches the exact role and that its application form or Apply link leads to an active intake for that requisition. Use a rendered browser when the raw page is only a JavaScript shell. For an inline form, the posting URL is also the application URL. Leave the form empty. If an Apply control might immediately send the application, inspect its visible destination or description without activating it. Mark the route unverified if that evidence is insufficient.
- **Closed.** Use this when the direct posting or its application page explicitly says closed, filled, expired, or no longer accepting applications, or when a previously identified exact posting is gone (including a 404, 410, or a redirect to a generic careers page). Look for the same requisition on the employer's site before concluding that it is closed. A similar title on a different requisition is a separate opportunity.
- **Unverified.** Use this for search-index or aggregator-only evidence, access blocks, sign-in walls, timeouts, or pages where you cannot establish the exact role or confirm its Apply route. Save what you observed when a job record exists. Follow the host's handoff process when user interaction could confirm the route.
- Start the final pass by capturing the current UTC timestamp with `node -e "console.log(new Date().toISOString())"`. Reopen every potential finalist's direct posting and confirm the application route in this pass, even if previously saved or checked. Record the outcome in `listing_verification` with `job add` or `job update` as described in `docs/COMMANDS.md`. Use the working direct URL if the same requisition moved and preserve the original saved listing.
- Run `node scripts/career.mjs job shortlist --since "<UTC timestamp from the start of this pass>"`. Use only candidates returned by this command in the live shortlist. Share their `posting_url`. Keep closed and unverified records out of the live count. When helpful, briefly explain any verification limits in chat.

## Evidence match

- Assess the posting's distinct, substantive qualifications and responsibilities. Include material gaps and combine overlapping bullets to avoid double counting. Mark explicit minimums and core responsibilities as `required`, and listed bonuses as `preferred`. Keep candidate preferences such as compensation and work arrangement in the ranking when relevant.
- Use `direct` for evidence that supports the requirement as written, `partial` for transferable or incomplete evidence, `gap` for a known shortfall, and `unknown` for an unverified requirement. Attach saved evidence IDs for direct and partial credit and provide a brief reason for each rating. Missing evidence alone is `unknown`.
- The helper multiplies required criteria by 2 and preferred criteria by 1. Direct, partial, gap and unknown earn full, half, zero and zero credit respectively. It divides earned points by available points and rounds the percentage to a whole number. Show the value returned by the helper. Leave a job unscored when the listing or career record is too thin for a meaningful assessment. Reassess when better evidence becomes available.
