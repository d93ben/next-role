# Prepare and track an application

1. Identify the exact saved job. If the user asks to apply to an unsaved job, first read/save its listing, then set `queued` with their request. “Prepare” authorizes preparation; it does not by itself authorize submission.
2. Read the saved listing, current profile, relevant experience facts, and previous documents. Match requirements to facts, not keywords alone. Ask focused questions when an important claim is missing. Save answers before using them.
3. Use this drafting brief for the exact role and employer.

   > Draft a resume for this job using the posting and the candidate's saved experience. Identify the most important requirements and lead with the candidate's strongest supported examples. Use the employer's terms where they accurately describe the candidate's work. Write concise bullets that show the candidate's action and the result where known. Keep job titles, employers, dates, and metrics accurate. Read the top third as a recruiter on a first pass and check whether the candidate's strongest qualifications are easy to find. Put material gaps in the review notes.

   Build the payload with a supported headline and summary, selected existing skills, and experiences in reverse chronological order unless the user requests a different order. Reference one or more fact IDs from the corresponding experience for every bullet. Review the meaning of each claim against its source before saving.
4. Use the built-in single-column Word template by default. Select, order and tailor the content for the role. For meaningful rewrites, include a short `rationale` naming the job requirement and a `source_excerpt` with the source ID and an exact, short quote when available. Record broader choices about the headline, summary, skills and omissions in `tailoring_notes`.
5. Run `resume create` and deliver the actual DOCX. If the employer or user requests PDF, export a text-based PDF with an available renderer, check it and import it with `document add`. Check the employer-facing file for accuracy, reading order, contact details, section headings, dates and bullets. Inspect pagination when rendering is available. Address gaps with supported wording or omit unsupported claims so the finished file can be delivered in the same turn. Prepare a cover letter when requested.
6. Mark `ready` after the requested documents are prepared and checked. For external submission, follow the user's authorization and host requirements. If there is a required handoff, leave the real application ready and say exactly what remains.
7. Record submission only when observed or reported by the user. Supply the exact `resume_id`, optional `attachment_ids`, date, evidence type, and concise evidence. If the user submitted a PDF exported from an HTML draft, import and archive the actual PDF they used rather than treating the HTML as the submitted file. The helper archives selected bytes with hashes; it does not submit anything.
8. When the user expresses interest in pursuing a specific role, complete the starter interview prep in `interview.md` using this resume before handing the work back. Reuse prior research for the same role. Honor narrower requests such as “resume only.” Keep the job at its evidenced stage.
9. Link the finished resume in chat. Show a compact comparison of the most consequential changes with original wording and source name, final wording, and why each change matters for this posting. If only a saved experience fact is available, label it as such. Mention significant omissions and why. Summarize the saved interview prep and give one next action, such as answering the first practice question. Record any known deadline. For a required submission handoff, give the exact remaining action.
