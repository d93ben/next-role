# Prepare and track an application

1. Identify the exact saved job. If the user asks to apply to an unsaved job, first read/save its listing, then set `queued` with their request. “Prepare” authorizes preparation; it does not by itself authorize submission.

   For a new application, reopen the exact posting and recheck its Apply route using `job-search.md`. Save the result. If the opening is closed, tell the user before preparing materials for that application. If availability is unverified, disclose the limit and continue any requested drafting or interview practice using the saved details. Recheck before any later application handoff or submission. Interview preparation for an existing application can proceed based on the interview context.
2. Read the saved listing, current profile, relevant experience facts, and previous documents. Match requirements to facts, not keywords alone. If the role has no evidence assessment or new information changes the match, follow the rubric in `job-search.md` and save the computed assessment when the evidence is sufficient. Ask focused questions when an important claim is missing. Save answers before using them.
3. Use this drafting brief for the exact role and employer.

   > Draft a resume for this job using the posting and the candidate's saved experience. Identify the most important requirements and lead with the candidate's strongest supported examples. Use the employer's terms where they accurately describe the candidate's work. Write concise bullets that show the candidate's action and the result where known. Keep job titles, employers, dates, and metrics accurate. Read the top third as a recruiter on a first pass and check whether the candidate's strongest qualifications are easy to find. Put material gaps in the review notes.

   Build the payload with a supported headline and summary, selected existing skills, and experiences in reverse chronological order unless the user requests a different order. Reference one or more fact IDs from the corresponding experience for every bullet. Review the meaning of each claim against its source before saving.
4. Check the workspace index for the user's template preference. For the default layout, run `resume create` with the supported content. For a saved template, fill a copy using the host's document tools and export a text-based PDF. Pass the finished `pdf_path` and the matching editable `docx_path` when available. If the built-in PDF renderer reports an unsupported character, render the verified content with a Unicode-capable document tool and pass its PDF. Keep character spelling intact. Use the template solely for layout. For meaningful rewrites, include a rationale and an exact source excerpt where available.
5. Deliver the current PDF with the filename returned by the helper. Inspect text extraction, pagination, contact details and reading order. In the first delivery, if `offer_template_in_chat` is true, say “If you have a résumé template you like, drop it into this chat and I’ll use it for this résumé and future drafts.” Record the invitation with `profile set` using `{"resume_template_offered":true}` as part of that handoff. The first draft is delivered immediately. When a template arrives, preserve the original under `workspace/templates/`, save its relative `resume_template_path` in the profile, and revise the current role. For a layout change, review the supplied PDF and editable copy together. Explain when an available editable copy uses the standard layout.
6. Mark `ready` after the requested documents are prepared and checked. For external submission, follow the user's authorization and host requirements. If there is a required handoff, leave the real application ready and say exactly what remains.
7. Record submission only when observed or reported by the user. Supply the exact `resume_id`, optional `attachment_ids`, date, evidence type, and concise evidence. Record the exact PDF used. Import an externally edited or previously submitted PDF first. If the user reports submitting another format, preserve their account in a job note and the original file as an imported document. Never claim a later conversion was the file they sent. The helper archives selected bytes with hashes; it does not submit anything.
8. When the user expresses interest in pursuing a specific role, complete the starter interview prep in `interview.md` using this resume before handing the work back. Reuse prior research for the same role. Honor narrower requests such as “resume only.” Keep the job at its evidenced stage.
9. Link the finished resume in chat. Show a compact comparison of the most consequential changes with original wording and source name, final wording, and why each change matters for this posting. If only a saved experience fact is available, label it as such. Mention significant omissions and why. Summarize the saved interview prep and give one next action, such as answering the first practice question. Record any known deadline. For a required submission handoff, give the exact remaining action.
