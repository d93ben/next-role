# Prepare and track an application

1. Identify the exact saved job. If the user asks to apply to an unsaved job, first read/save its listing, then set `queued` with their request. Treat even an explicit request to submit as a request to prepare the application for the user's final action.

   For a new application, reopen the exact posting and recheck its Apply route using `job-search.md`. Save the result. If the opening is closed, tell the user before preparing materials for that application. If availability is unverified, disclose the limit and continue any requested drafting or interview practice using the saved details. Recheck before a later application handoff. Interview preparation for an existing application can proceed based on the interview context.
2. Read the saved listing, current profile, relevant experience facts, and previous documents. Match requirements to facts, not keywords alone. If the role has no evidence assessment or new information changes the match, follow the rubric in `job-search.md` and save the computed assessment when the evidence is sufficient. Ask focused questions when an important claim is missing. Save answers before using them.
3. Use this drafting brief for the exact role and employer.

   > Draft a resume for this job using the posting and the candidate's saved experience. Identify the most important requirements and lead with the candidate's strongest supported examples. Use the employer's terms where they accurately describe the candidate's work. Write concise bullets that show the candidate's action and the result where known. Keep job titles, employers, dates, and metrics accurate. Read the top third as a recruiter on a first pass and check whether the candidate's strongest qualifications are easy to find. Put material gaps in the review notes.

   Build the payload with a supported headline and summary, selected existing skills, and experiences in reverse chronological order unless the user requests a different order. Reference one or more fact IDs from the corresponding experience for every bullet. Review the meaning of each claim against its source before saving.
4. Use the current layout from `resume_template_path`. With no selection, use the built-in default. If the user tells you a template was selected by mistake, return to the default using the replacement command in `docs/COMMANDS.md`. Keep their original upload as career material.

   For a selected DOCX, run `template inspect` with the same CLI used for other workspace commands. Map the résumé's verified wording onto the numbered template paragraphs, including sample names, contact information, headers and footers. Send `template_edits` with the normal evidence-backed `resume create` payload. It fills a copy and prints that copy to PDF in the background. For edits to fields, links, drawings or table structure, fill a copy programmatically with a document library and supply its `docx_path` to the same command. See `docs/COMMANDS.md` for examples. Use file-based tools for drafting, export and review. Do not launch Word, request desktop control or ask the user to install an office suite.

   The inline editor requires a DOCX. For a selected PDF or other layout, use a suitable file-based renderer and pass a checked `pdf_path`. Disclose any layout limitation before offering a substitute. If a selected original is missing, recover it from the existing materials or ask for that file. For meaningful rewrites, include a rationale and an exact source excerpt where available.
5. Deliver the current PDF and inspect text extraction, pagination, contact details, reading order and chosen layout. For a template, also check that sample wording was replaced, links point to the candidate, and the editable copy matches. Offer a template once when `offer_template_in_chat` is true. For example, “If you'd like me to reuse a specific layout, attach it and say ‘use this as my template.’” Record the invitation with `profile set` using `{"resume_template_offered":true}` at delivery. Deliver the first draft without waiting for a template.

   To select a template, preserve the supplied original under a distinct path in `workspace/templates/` and save its relative `resume_template_path` with `profile set`. The first template applies to the current draft and future roles. Once one is active, treat later uploads as reference material unless the user tells you to use a replacement. For an explicit switch, include the current path as `replaces_resume_template_path` in the same update. Preserve the existing original even if the new upload has the same filename. Use the new layout for the current draft and subsequent résumés. For an editable copy, identify whether it matches the template.
6. Mark `ready` after the requested documents are prepared and checked. Always stop before the action that sends the application. Leave the form at review when possible. For a one-click or ambiguous Apply button, hand off before clicking it. For an application by email, leave a draft. Give the user the posting or draft, the exact files, any fields still open, and the action they must take themselves. Keep the job at `ready` while awaiting submission.
7. After the user reports they submitted or you see an employer confirmation for that role, use `submission record`. Approval to proceed and a completed form are insufficient evidence. Supply the exact `resume_id`, optional `attachment_ids`, date, evidence type, and concise evidence. Record the exact PDF used. Import an externally edited or previously submitted PDF first. If the user reports submitting another format, preserve their account in a job note and the original file as an imported document. Never claim a later conversion was the file they sent. The helper archives selected bytes with hashes; it does not submit anything.
8. When the user expresses interest in pursuing a specific role, complete the starter interview prep in `interview.md` using this resume before handing the work back. Reuse prior research for the same role. Honor narrower requests such as “resume only.” Keep the job at its evidenced stage.
9. Link the finished resume in chat. Show a compact comparison of the most consequential changes with original wording and source name, final wording, and why each change matters for this posting. If only a saved experience fact is available, label it as such. Mention significant omissions and why. Summarize the saved interview prep and record any known deadline. For an application handoff, end with the user's next step, for example, "Review the attached PDF and click Submit yourself. Tell me once you've sent it so I can record it."
